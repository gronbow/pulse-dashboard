# PR B：逐项数据可信度与紧凑模式防误读

## 目标

Pulse 需要明确区分三件事：数据通过什么通道到达、数据最初来自哪里、单项指标实际对应哪一天。当前界面已经显示快照日期和总体来源，但单项日期缺失、旧值和缓存状态仍可能被误读为“今天的新数据”。

本阶段为健康指标、今日训练、训练计划和负荷趋势建立统一的数据可信度呈现，并让紧凑模式在不增加大量文字的前提下显示关键日期状态。

## 设计原则

- 保留快照 v2，新增字段保持可选，旧插件和旧快照继续可读。
- `meta.source` 只描述传输状态，例如 bridge、cache、demo 或 unavailable。
- `provenance` 只描述单项数据来源，允许值为 `coros`、`derived`、`user`、`demo`、`local`、`mixed` 或 `unknown`。
- 单项日期与当前日期比较后统一归类为 `current`、`recent`、`old`、`unknown` 或 `unavailable`。
- 缺少日期时显示“日期未知”，不得默认为今天。
- 缺少来源时显示“来源未知”，不得从自由文本猜测。
- 紧凑模式优先显示日期状态；完整模式同时显示日期与来源。
- 可信度颜色只表达数据状态，不表达健康好坏或训练许可。
- 不增加医学阈值，不改变 readiness 安全门，不让 Electron 直接调用 COROS MCP。

## 界面行为

- 六张健康卡片增加小型可信度标签，例如“今日 · COROS”“8月12日 · COROS”“日期未知 · 来源未知”。
- 今日训练、训练计划和近 7 日状态显示组级来源与日期。
- 16:9、4:3 和 21:9 紧凑卡片在单位行中显示简短日期；完整来源保留在可访问名称和悬浮说明中。
- 快照整体来自缓存时，顶部继续显示缓存状态；卡片来源仍显示原始 provider，避免把传输状态误写成数据来源。
- 不可用值显示“暂无数据”，并使用中性色，而不是制造 0 或绿色“新鲜”状态。

## 安全与隐私

- `provenance` 使用固定枚举，拒绝任意来源字符串进入发布快照。
- 渲染活动和洞察标签时使用 DOM 节点与 `textContent`，移除对 HTML 字符串拼接的依赖。
- 不写入 MCP 工具名、内部活动 ID、坐标、令牌、用户路径或原始响应。
- Handoff JSON 响应增加 `X-Content-Type-Options: nosniff`。

## 验收标准

- 纯函数测试覆盖今天、昨日、旧日期、未知日期、缺失值、显式来源、继承属性和原型污染输入。
- 快照归一化与发布门覆盖 provenance 枚举和向后兼容路径。
- Electron 测试覆盖完整模式和三种紧凑比例中的旧值、未知日期和来源说明。
- 深色、浅色、100%/125%/150% DPI 均无文字溢出。
- `npm run test:ci`、公开仓库审计、历史审计和插件校验全部通过。

## 非目标

- 不合并 PR #12，不推送 PR B，不创建 Release 或安装包。
- 不处理独立 OAuth、自动后台 MCP 查询、代码签名或跨平台迁移。
- 不在本阶段合并 Dependabot 的 `@electron/fuses` 主版本升级。
